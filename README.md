# 🚀 Full-Stack Engineering Mastery

A 3-year private software-engineering degree, from "how does a computer work?" to designing, deploying and operating production systems.

> The target is: **I can design, build, test, secure, deploy, operate, scale, document and explain a production software system.**

**New here? Start with [00.Orientation](00.Orientation/README.md), then [Month 01 · Week 1 · Day 1](Year1.Foundations-Frontend/M01.ComputingFundamentals/W1.HowComputersRunPrograms/D1.WhatIsSoftwareEngineering/README.md).**

## 📅 The weekly study system

| Day | Purpose |
|---|---|
| **D1** Monday | Theory + fundamentals |
| **D2** Tuesday | Deeper concepts + examples |
| **D3** Wednesday | Guided implementation |
| **D4** Thursday | Independent implementation |
| **D5** Friday | Debugging + architecture exercise |
| **D6** Saturday | Project work |
| **D7** Sunday | Review + quiz + reflection |

Missed a day? Don't skip it. Days are numbered, not dated, so just continue where you stopped.

## 🧩 Every lesson has the same 10 parts

1. **Concept**: what it is (a simple analogy first, then the precise words)
2. **Why it exists**: the problem it solves
3. **Internal mechanics**: what happens underneath
4. **Simple example**: small and controlled (runnable in `Examples/`)
5. **Real-world example**: a production scenario
6. **Coding exercise**: you write it (`Exercises/`, with automated tests)
7. **Debugging challenge**: you get broken code (`Debugging/`)
8. **Architecture question**: how would you design it?
9. **Short assessment**: quiz, with answers hidden
10. **Reflection**: explain it in your own words. *If you can't explain it simply, you don't understand it yet.*

## 🧠 Three layers for everything

| Layer | Question | Example (React) |
|---|---|---|
| 1 | How do I **use** it? | How do I build components? |
| 2 | How does it **work**? | How does React rendering work? |
| 3 | **When** should I use it (and when not)? | Is React right for this architecture? |

Layer 3 is where engineering judgment grows.

## ✅ Progress gates

You pass a stage only when you can: **Explain it · Implement it · Debug it · Use it in a project · Explain its trade-offs.**
A month ending is *not* a reason to move on. Track everything in [PROGRESS.md](PROGRESS.md).

## 🛠️ How this course is built

- **The whole map exists now:** every month has a README with outcomes, topics, a 4-week plan, a project, the three layers and a gate.
- **Detailed daily lessons are written one month at a time**, just ahead of you. That keeps them current (tools change over 3 years) and lets them adapt to your weak spots from the previous exam.
- Folder pattern for a day: `README.md` (the 10 parts) · `Examples/` · `Exercises/NN_Name/` · `Debugging/NN_Name/` · `MY-NOTES.md` (yours).
- Each exercise folder has `main.js` (your work), `main.test.js` (the automatic checker) and `solution/` (look only after trying!).

### Tools

| Command (run from the course folder) | What it does |
|---|---|
| `node --test` *(inside an exercise folder)* | Checks **your** solution |
| `powershell -ExecutionPolicy Bypass -File tools\check-exercises.ps1` | Proves every model solution in the course passes |
| `powershell -ExecutionPolicy Bypass -File tools\sync-vscode.ps1` | Copies the VS Code setup into every lesson folder |
| `powershell -ExecutionPolicy Bypass -File tools\new-lesson.ps1 -Path <folder>` | Scaffolds a new day lesson from the template |

In VS Code: **Ctrl+Shift+B** runs the open file · **Ctrl+Shift+P → "Tasks: Run Test Task"** tests the current exercise · **F5** debugs.
